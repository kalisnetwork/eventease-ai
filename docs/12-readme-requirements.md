# 12 — Final README requirements

The public GitHub README must contain all of the following, and must be accurate
about what exists.

1. **Project name and overview.**
2. **Problem statement.**
3. **Target users.**
4. **Features implemented** — with implemented vs planned clearly separated.
5. **How the AI works** — provider, server-side flow, structured output,
   validation, confirmation before writes, failure handling.
6. **Technology stack.**
7. **Architecture overview** — diagram or concise description, data model summary.
8. **Installation instructions** — prerequisites, install, env, migrate, run.
9. **Environment configuration** — every variable, purpose, where to obtain it.
10. **Database setup** — migrations, seeding (if any), reset.
11. **Test commands and actual test status** — state what was run and the result.
12. **Deployment URL.**
13. **Security considerations** — auth, authorization, secrets, rate limits,
    input validation, AI safety.
14. **Known limitations** — vendor directory is user-managed, no live discovery,
    no real messaging, no payments, single currency, etc.
15. **Assumptions.**
16. **AI tools and services used** — model provider, libraries, any coding agents.
17. **Screenshots or a demonstration link.**

## Style

- Start with a one-paragraph description a non-technical reader understands.
- Use short sections and tables where helpful.
- Include a screenshot of the dashboard and one of the AI flow.
- No badges claiming passing tests or deployments unless verified.
- No invented metrics ("used by 10,000 organisers").

## Accuracy checklist

- [ ] Every feature listed is implemented and reachable.
- [ ] Planned work is under a "Roadmap" heading.
- [ ] Test status reflects the last real run.
- [ ] Deployment link works.
- [ ] Demo credentials (if any) are labelled as demo-only.
- [ ] Limitations section is honest.
- [ ] No secrets or personal data in screenshots.
